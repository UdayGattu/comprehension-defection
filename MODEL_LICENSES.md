# Model licences and the licence of the released data

This repository distributes **no model weights**. It distributes code (MIT, see
`LICENSE`), documentation, and SQLite databases that contain **text generated by
three third-party models**. Those generations are what makes this file
necessary: the data licence cannot be stated without stating the terms the
generations came under.

Nothing here is legal advice. It is a record of what is in the release and which
terms attach to it, so that a reviewer or a re-user can check rather than guess.

---

## 1. What in the data is model output

Model-derived text lives in the `turn_details` table (schema: `cdx/db.py`):

| column | content | model-derived |
|---|---|---|
| `turn_details.scratchpad` | the model's chain-of-thought text, SCRATCHPAD readout | **yes** |
| `turn_details.probe_answers` | the model's raw answers to the comprehension probes | **yes** |
| `turn_details.top_tokens` | top-K token strings and probabilities from the model's next-token distribution | **yes** (token strings + logprobs) |
| `turn_details.prompt_full` | the complete decoded prompt, first 3 episodes per cell | no — authored by this study |
| `turn_details.prompt_preview` | first+last 300 chars of the assembled prompt | no |
| `turns.agent_action` | `C`/`D`, the action the readout resolved to | derived, not text |
| everything else | engine state, payoffs, seeds, provenance | no |

`turn_details.scratchpad` is populated for the SCRATCHPAD groups of exp4, exp5
and exp6 (exp5 records 120,000 of 120,000 turns producing non-trivial
scratchpads). `probe_answers` and `top_tokens` are present across the corpus.

Which models appear in which databases follows the filename: `*_llama_*` are
Llama-3.1-8B-Instruct, `*_qwen_*` are Qwen2.5-7B-Instruct, `*_mistral_*` are
Mistral-7B-Instruct-v0.3. `sweep.sqlite.gz` (exp1) is Llama only. `run_meta`
records `model_id` for every run and is authoritative.

## 2. meta-llama/Llama-3.1-8B-Instruct — **gated, not Apache-2.0**

Distributed under the **Llama 3.1 Community License Agreement**, plus Meta's
Acceptable Use Policy. It is a bespoke community licence, not an OSI-approved
open-source licence, and access on Hugging Face is **gated**: you must accept
the terms and supply an `HF_TOKEN`. Every GPU driver in `scripts/` aborts if
`HF_TOKEN` is unset, for this reason.

Terms:

- Licence text: <https://github.com/meta-llama/llama-models/blob/main/models/llama3_1/LICENSE>
- Acceptable Use Policy: <https://www.llama.com/llama3_1/use-policy/>
- Model card: <https://huggingface.co/meta-llama/Llama-3.1-8B-Instruct>

Obligations that apply to **this release**, because the release contains
Llama-3.1 outputs:

1. **Attribution.** Redistribution of the model, a derivative, or a product
   using it must display "Built with Llama". This repository does so, in
   `README.md` and in section 5 below.
2. **Naming of derivatives.** If any model is trained, fine-tuned or otherwise
   improved using Llama outputs — which the databases in this repository
   contain, and the Llama 3.1 licence permits — the resulting model's name must
   begin with "Llama". Anyone using `turn_details.scratchpad` or
   `turn_details.probe_answers` from the `*_llama_*` databases as training data
   inherits that obligation. It does not attach to the `*_qwen_*` or
   `*_mistral_*` databases.
3. **Licence propagation.** A copy of the Llama 3.1 Community License must
   accompany any redistribution of Llama materials or derivatives thereof.
4. **Acceptable Use Policy.** Use of the Llama-derived material remains subject
   to it.
5. **Scale clause.** The licence's grant is conditioned on the licensee not
   exceeding 700 million monthly active users as of the Llama 3.1 release date;
   above that a separate licence from Meta is required. Recorded here for
   completeness; it does not bind an academic re-user.

## 3. Qwen/Qwen2.5-7B-Instruct — Apache-2.0

<https://huggingface.co/Qwen/Qwen2.5-7B-Instruct> — released under
**Apache License 2.0**. No gating, no naming obligation on derivatives, no
attribution string required beyond the usual Apache-2.0 notice and licence
retention when redistributing the weights themselves (which this repository does
not do).

## 4. mistralai/Mistral-7B-Instruct-v0.3 — Apache-2.0

<https://huggingface.co/mistralai/Mistral-7B-Instruct-v0.3> — released under
**Apache License 2.0**. Same position as Qwen: no gating, no naming obligation,
nothing attaches to the generations in this release beyond attribution as a
courtesy.

Note that the Mistral repository on Hugging Face may still require accepting
usage terms before download even though the licence is Apache-2.0; that is an
access control, not a licence restriction.

## 5. Licence of the released data

**The databases (`*.sqlite.gz`) and the prose documentation in this repository
are released under Creative Commons Attribution 4.0 International (CC BY 4.0)**
— <https://creativecommons.org/licenses/by/4.0/> — subject to the third-party
terms in sections 2–4, which this study cannot waive on the model providers'
behalf.

In practice:

- Re-use, redistribute, and build on the data, including commercially, with
  attribution (see `CITATION.cff`).
- The `*_llama_*` databases carry the Llama 3.1 obligations in section 2. In
  particular, training a model on the Llama-derived generations obliges you to
  name it beginning with "Llama".
- The `*_qwen_*` and `*_mistral_*` databases carry no such condition.
- The code stays MIT (`LICENSE`); CC BY 4.0 is not a software licence and is not
  applied to it.

## 6. Human-subjects and personal data

None. Every prompt in the corpus is generated by `cdx/scaffold.py` from a fixed
template and engine state; no human wrote any input, and no personal data is
present in any database. The only free text is model-generated
(`scratchpad`, `probe_answers`) or study-generated (`prompt_full`).
